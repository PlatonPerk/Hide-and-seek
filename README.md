# Нычка — прятки в СберKids

Прототип для хакатона «Сбер — Создаем эмоции», трек A «Приколы».
Команда: Платон, Степа, Никита, Федя и Тимур креветки.

Раз в день персонаж Нычка прячется в одном из разрешённых мест интерфейса. Ребёнок находит его тапом.
Место выбирается по весам из контент-конфига и в один день одинаково у всех.

## Что уже есть

- Нативный Android-прототип на Kotlin + Jetpack Compose (тот же стек и версии, что в песочнице организаторов).
- Вкладки «Главный», «Копилки», «Дела», «Контент», сверстанные по макетам Figma, и плавающий таб-бар с лапкой.
- Слой мест для пряток. Элементы экранов размечены модификаторами `Modifier.hideSpot(id)` (сюда прятаться можно)
  и `Modifier.noHideZone(id)` (сюда нельзя: кнопки оплаты и переводов, баланс, операции, реклама).
  Координаты мест обновляются при скролле. Таб-бар помечен как `occluder`: места, уехавшие под него,
  из выбора исключаются (`HideSpotRegistry.visibleAllowed()`).
- Отклик на нажатия: все кнопки, плитки и карточки проседают под пальцем и пружинят обратно
  (`Modifier.tappable`), с рябью и лёгкой вибрацией. Карта на «Главном» подпрыгивает по тапу,
  фильтры в «Контенте» переключаются, лайк и «играть/пауза» срабатывают.
- Нычка прячется по-настоящему: модуль `hideandseek` рисует её поверх экранов у места дня,
  тап засчитывает находку (анимация, вибрация, карточка «Нашёл!» с советом дня).
- Отладочный режим: **долгое нажатие на лапку** в таб-баре показывает все места на экране
  и **панель демо**. Зелёные рамки — разрешённые места, серые — места под таб-баром, красные — запретные зоны.
  В панели: где Нычка сегодня, «◀ день / день ▶» (перемотка дней), «Спрятать снова»,
  «Обновить контент», «Перепрятка», «Сбросить находки».
- Режим демо «Перепрятка» (включён в прототипе, `NychkaConfig.DEMO_REHIDE` в `MainActivity.kt`):
  после находки и закрытия карточки «Нашёл!» Нычка сразу прячется на другом экране (другой вкладке),
  с новым советом дня. Где она сейчас, видно в панели демо. В настоящем приложении режим выключен:
  одна находка в день.

## Как запустить

1. Открыть папку проекта в Android Studio (JDK 21).
2. Запустить конфигурацию `app` на телефоне (Android 8+) или в эмуляторе.

Готовые APK собираются автоматически на каждый пуш в `main` и лежат в ветке
[`ci-results`](../../tree/ci-results) и в артефактах GitHub Actions:

- `nychka-release.apk` — **для демо**: R8, без отладочного режима, плавный скролл;
- `nychka-debug.apk` — для отладки (Compose в debug-сборке заметно медленнее).

Обе подписаны общим демо-ключом из репозитория, поэтому ставятся поверх друг друга.
Там же лежат рендеры экранов (`01_main.png`, …) и лог сборки.

Рендер экранов локально, без телефона:

```bash
./gradlew :app:recordRoborazziDebug   # картинки → app/build/outputs/roborazzi/
```

## Как это встраивается в настоящий СберKids

```kotlin
// 1. Один раз в корне приложения: контроллер и слой поверх всех экранов
val hideAndSeek = rememberHideAndSeekController(source = ContentSource { cms.getJson("hide_seek_config") })
HideAndSeekHost(hideAndSeek, Modifier.fillMaxSize()) {
    AppRoot()
}

// 2. Повесить якоря на существующие элементы экрана (id = id места в контенте)
Banner(modifier = Modifier.hidingSpot("main.banner"))

// 3. На экранах оплаты, переводов, реквизитов и лимитов
HideAndSeekBlocker()
```

В прототипе это сделано в `MainActivity.kt`, а `Modifier.hideSpot(id)` из `hidespots/HideSpots.kt`
одновременно регистрирует место и в отладочном реестре, и в модуле.

На iOS тот же приём делается через `anchorPreference` / `GeometryReader` в SwiftUI.

## Иллюстрации

Картинки вырезаны из скриншотов Figma в плотности hdpi (~1,5 px на dp). На телефоне они немного мягче оригинала.
Чтобы стало чётче, экспортируйте их из Figma в @3x, положите в `res/drawable-xxhdpi/` с теми же именами
и удалите файлы из `drawable-hdpi/`.

## Модуль «Прятки»

Логика и слой с персонажем живут в отдельном модуле `hideandseek` (подключён в `app` через
`implementation(project(":hideandseek"))`). Подробности, формат контента и шаги встраивания —
в [`hideandseek/README.md`](hideandseek/README.md).

## Контент без релиза

Приложение скачивает [`content/hideandseek.json`](content/hideandseek.json) прямо из этого репозитория
(`NychkaConfig.CONTENT_URL` в `MainActivity.kt`); без сети берёт кеш или копию из
`app/src/main/assets/hideandseek/content.json`. Чтобы поменять места, веса, тексты или персонажа:

1. Отредактировать `content/hideandseek.json` на GitHub и сохранить.
2. В приложении: долгое нажатие на лапку → «Обновить контент» (или перезапуск).

`id` мест в JSON должны совпадать с `hideSpot("…")` на экранах. В `specialDays` задано, где Нычка
прячется в день защиты (18.10 — баннер на «Главном»). После правки JSON стоит обновить и копию в `assets`.

Что где лежит в JSON:

- `tips` — советы для карточки «Нашёл!» (строка или `{ "text", "from", "to" }` для сезонных).
  В обычном режиме совет один на день; в режиме «Перепрятка» каждая новая находка показывает другой.
- `texts` — заголовок карточки, текст про укрытие, строка про серию дней, подпись «Совет дня».
- `look.messageMs` — сколько карточка висит, в мс (сейчас 7 000, максимум 30 000). Раньше её можно убрать,
  смахнув вверх или переключив вкладку; касания по карточке и мимо неё её не закрывают.
  Если лиса выходит у верха экрана, карточка встаёт под ней, чтобы её не закрывать.

## Лиса Нычка: позы

Позы лежат в `app/src/main/assets/hideandseek/nychka/` (WebP с прозрачностью, ~3 px на dp) и подключаются
в контенте полем `sprites` у зверька. Золотая и Снежная Нычка берут те же позы через `"spritesFrom": "nychka"`
и отличаются цветом карточки и искорками.

| Поза | Файл | Когда | Якорь `anchor` |
|---|---|---|---|
| `peek` | `peek.webp`, `peek_blink.webp` | прячется за верхним краем элемента | середина между лапами на линии края |
| `side` | `side.webp`, `side_blink.webp` | прячется за правым краем (для левого зеркалится) | лапа на линии стены |
| `found` | `surprised.webp` | сразу после тапа: «поп» и маленький прыжок | ноги |
| `celebrate` | `celebrate.webp` | два прыжка поверх звёздочек | ноги |
| `run` | `run.webp` | убегает за ближайший край экрана | ноги |

- `heightDp` — высота позы на экране, ширина берётся из картинки. Позы нарисованы в разном масштабе,
  поэтому высота у каждой своя: так голова лисы примерно одного размера во всех позах.
- Кадр моргания (`blink`) должен совпадать с позой по размеру — он подменяет её целиком.
- Новую позу или другой зверёк можно положить на CDN и поменять только адреса в JSON (`https://…`).
- Для нижнего края элемента позы нет: там рисуется прежний зверёк кодом. Места снизу лучше не заводить.
- Боковые места — только на высоких элементах (свинка в «Копилках», маскот «Алгоритмики»):
  у короткого заголовка голова лисы торчит выше него, поэтому места у заголовков убраны.
- Выход лисы после находки привязан к элементу: при прокрутке едет вместе с ним,
  при смене вкладки исчезает.
- Код: загрузка и рисование поз — `hideandseek/.../Poses.kt`, выглядывание и выход после находки — `Overlay.kt`.
